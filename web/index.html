    01 · PROVIDERS

    Endpoints and credentials

    Configure each provider once. Every stage below picks from this list, so no endpoint or key is ever entered twice.

    Configure once
    Embedding providerOne per workspace — the Index stage always uses it.
    Required

    The local provider is private and ready immediately. Switching model or dimensions re-embeds the corpus after saving.

    Default LLM providerWhat a stage runs on unless it picks another connection, and what answers Ask, Wiki and Dream.
    Default

    Other connectionsAdd one when a stage needs a different endpoint — a vision-capable API, a cheaper model, a second key.

    02 · PIPELINE

    What each stage needs

    A document moves down this list. The stages ask different things of a model, which is why each one can run somewhere else.

    Per stage
    1

    Convert

    Vision

    Images and scanned PDF pages become searchable Markdown.

    The model has to see pixels: an API provider gets the image inline, codex takes --image, and claude and cursor read the file with their own tools. A text-only model fails here. Changing this re-converts every image and scanned page.

    2

    Index

    Embedding

    Every chunk becomes a vector for semantic and hybrid recall.

    Not an LLM — it uses the embedding provider from section 01, one per workspace. Changing its model or dimensions re-embeds the whole corpus.

    Runs on Loading… Set in section 01 · Embedding provider
    3

    Extract

    Volume

    Names entities, relations and factual claims in changed documents.

    The busiest stage — it runs on every changed document, bounded by the daily budget and batch size below. A fast, cheap model that returns clean JSON is usually the right trade.

    4

    Synthesize

    Quality

    Turns hot entity clusters into readable, linked Concept pages.

    Far fewer calls than Extract — only hot clusters reach it — and the output is prose people read, so a stronger model pays for itself here.

    5

    Answer

    Interactive

    Ask, wiki summaries and the nightly Dream analysis.

    Always the default provider. Latency lands straight in the Ask box, so prefer something responsive.

    Runs on Loading… Set in section 01 · Default LLM provider

    Pipeline controls

    Bound background work without changing the selected models.

    03 · DEEP RESEARCH

    Who writes the wiki, and how hard they think

    An agent researches a topic through the MCP endpoint and writes the page — either a coding-agent CLI on this machine, or the built-in agent running on an OpenAI-compatible connection. A profile sets the reasoning effort, web access and verification bar, and lists the sub-agents — each with its own CLI, model, tools and prompt.

    Agents
    Research agentWhich agent runs jobs, how many at once, and which profile it follows. Roles below may override the agent per phase.
    Runner

    InitializationWhat the Wiki tab's initialize button does before the agent starts, and how many topic pages it queues afterwards.
    Init
    ChatThe Chat tab uses the same agent research does: it answers over MCP, and writes what you teach it as a quarantined note.
    Chat
    Profile Stored as playbooks/research/profiles/<name>.yaml — edit here or in the file. The profile may pin its own pipeline.
    Sub-agentsOne card per role. Each has its own CLI, model, effort, tools and prompt; turn a role off to skip its phase. Several roles may share a phase (review roles all run; research roles split the sections).
